## 1. เป้าหมาย

หัวหน้าและเซลล์เปิดหน้าเดียวแล้วเห็นว่าลูกค้าอยู่กลุ่มไหนเท่าไร ควรทำอะไรกับแต่ละกลุ่ม และกดกลุ่มเพื่อกรองรายชื่อได้ทันที

1. **แผนที่กลุ่มลูกค้า** — ตาราง F × R (แกนตั้ง F = ความถี่ จำนวนครั้งที่ซื้อ · แกนนอน R = ซื้อล่าสุด จำนวนวัน) แต่ละกลุ่มเป็นบล็อกสีพร้อมจำนวนลูกค้า กดบล็อก = เลือกกลุ่ม
2. **Action Context ต่อกลุ่ม** — แนวทางทัก, พฤติกรรมลูกค้า, แคมเปญแนะนำ (ตาราง Segment guide ของผู้ใช้) แสดงข้างแผนที่เมื่อเลือกกลุ่ม
3. **รายชื่อลูกค้าของกลุ่มที่เลือก** — ตารางเดียวกับหน้าลูกค้าของฉัน (ติ๊ก → ส่งข้อความ / เข้า Direct Sale / จอง)
4. **ตั้งค่า RFM (หัวหน้า)** — แก้เกณฑ์ของแต่ละกลุ่มและ Action Context ได้เอง ดูผลก่อนบันทึก
5. **เตรียมข้อมูลให้เฟส AI** — Action Context เก็บเป็นข้อมูลต่อกลุ่มที่อ่านผ่าน RPC ได้ เฟสถัดไป (AI ร่างข้อความรายคน) หยิบไปเป็นบริบทได้เลย

### ไม่อยู่ในงานนี้

- AI ร่างข้อความ personalize (เฟสถัดไป) — งานนี้ไม่มีปุ่ม AI บนหน้าจริง และไม่มีช่อง "ข้อควรระวังสำหรับ AI" (ใน mockup วางไว้ให้เห็นตำแหน่งเท่านั้น)
- คะแนน M (Monetary) และคะแนน R/F แบบ 1–5
- เพิ่ม/ลบ/เปลี่ยนชื่อกลุ่ม และเลือกสีของกลุ่มเอง (10 กลุ่มคงที่ สีผูกกับกลุ่มในโค้ด)
- ตาราง R × F ในหน้า Dashboard, แคมเปญอัตโนมัติต่อกลุ่ม
- เปลี่ยนกติกา "ไม่ซื้อมา 30 วันขึ้นไปจึงจอง/ทักได้" (`dormant_days` setting, `customer_base.eligible`)

## 3. กลุ่มและกติกา

10 กลุ่มคงที่ (key = ชื่อกลุ่ม ใช้ค่าเดียวกับ `dsales_customer_base.rfm` และ `?rfm=` ใน URL เดิม) เช็กตามลำดับ ข้อแรกที่ตรง = กลุ่มนั้น
ค่าเริ่มต้น (seed) = กติกาปัจจุบันของ `dsales_rfm` + **แยก Hot ออกจาก Warm** (ผู้ใช้เห็นชอบ 2026-11-26):

| ลำดับ | กลุ่ม | F ตั้งแต่ | F ถึง | R ตั้งแต่ | R ถึง | แนวทางทัก (tone) |
|---|---|---|---|---|---|---|
| 1 | Champion | 6 | — | 0 | 30 | ดูแลพิเศษ |
| 2 | Shouldn't Lose | 6 | — | 91 | — | Hard winback |
| 3 | Loyal | 4 | — | 0 | 90 | กระตุ้นซื้อซ้ำ |
| 4 | Sleepers | 3 | — | 91 | — | Soft winback |
| 5 | Promising | 2 | — | 0 | 60 | Up-sell |
| 6 | Need Attention | 2 | — | 61 | 90 | Up-sell / Cross-sell |
| 7 | Hot | 1 | 1 | 0 | 30 | ต้อนรับ |
| 8 | Warm | 1 | 1 | 31 | 60 | Hard conversation |
| 9 | Cold | 1 | 1 | 61 | 90 | Soft conversation |
| 10 | Lost | (ที่เหลือทั้งหมด) | | | | หยุดส่ง |

- "—" = ไม่จำกัด · ไม่มีจำนวนออเดอร์ (< 1) หรือไม่มีวันซื้อล่าสุด = ไม่มีกลุ่ม (null) เหมือนเดิม
- Lost เป็นกลุ่มรับที่เหลือ (fallback) อยู่ท้ายสุดเสมอ ไม่มีช่วงให้แก้
- กติกาซ้อนกันได้ (ลำดับตัดสิน) ช่องว่างระหว่างกติกาตกไป Lost — หน้าตั้งค่าแสดงผลก่อนบันทึกให้เห็น
- พฤติกรรมลูกค้า / แคมเปญแนะนำ เริ่มต้น = ตาราง Segment guide ใน backlog (Hot ใช้แถว "New Customers", Warm ใช้ "Warm Leads", Cold ใช้ "Cold Leads")

**ผลของการแยก Hot:** Hot = ซื้อครั้งเดียว 0–30 วัน แต่ลูกค้าจะจอง/ทักได้เมื่อไม่ซื้อมา ≥ 30 วัน ดังนั้น Hot ที่ "ติดต่อได้ตอนนี้" มีเฉพาะคนที่ครบ 30 วันพอดี ส่วน Warm ในหน้าลูกค้าของฉัน/ถังกลางจะเหลือเฉพาะ 31–60 วัน

## 4. ฐานข้อมูล (schema `dsales` เท่านั้น) — migration `dsales_rfm_config`

### 4.1 ตาราง `dsales_rfm_segments` (ภายใน ไม่มี grant)

| คอลัมน์ | ชนิด | หมายเหตุ |
|---|---|---|
| `key` | text PK | ชื่อกลุ่ม 10 ค่าคงที่ |
| `sort_order` | int unique | ลำดับเช็กกติกา |
| `f_min`, `f_max` | int, int null | ช่วงความถี่ (รวมขอบ) null = ไม่จำกัด |
| `r_min`, `r_max` | int, int null | ช่วงวันที่ไม่ได้ซื้อ (รวมขอบ) |
| `is_fallback` | boolean | true เฉพาะ Lost |
| `tone` | text | แนวทางทัก (ข้อความสั้น) |
| `behavior` | text | พฤติกรรมลูกค้า |
| `action` | text | แคมเปญแนะนำ |
| `template_bebeplay`, `template_hosttail` | uuid null → `dsales_templates(id)` on delete set null | template เริ่มต้นต่อแบรนด์ |
| `no_outreach` | boolean default false | ไม่ส่งข้อความเป็นชุดให้กลุ่มนี้ |
| `updated_at`, `updated_by` | timestamptz, uuid | |

seed 10 แถวตามข้อ 3 · `no_outreach` เริ่มเป็น false ทุกกลุ่ม (รวม Lost) เพื่อไม่เปลี่ยนพฤติกรรมการส่งจนกว่าหัวหน้าจะเปิดเอง

### 4.2 การคำนวณกลุ่ม

- `dsales_rfm(p_orders int, p_days int)` เปลี่ยนจาก immutable (สูตรตายตัว) เป็น **stable อ่านกติกาจาก `dsales_rfm_segments`** (ลายเซ็นเดิม สิทธิ์เดิม: ไม่ grant)
- `dsales_customer_base.rfm` เปลี่ยนจากคอลัมน์ generated เป็นคอลัมน์ปกติ (`alter column rfm drop expression` — ค่าเดิมคงอยู่ ชื่อคอลัมน์เดิม ฟังก์ชันที่อ่าน `b.rfm` ไม่ต้องแก้)
- trigger `before insert or update of order_count, dormant_days` บน `dsales_customer_base` ตั้ง `new.rfm := dsales_rfm(new.order_count, new.dormant_days)` → refresh รอบ cron ทำให้กลุ่มถูกต้องเองเหมือนตอนเป็น generated โดย**ไม่ต้องแก้ `dsales_refresh_customer_base()`**
- `dsales_rfm_apply()` (ภายใน): `update dsales_customer_base set rfm = dsales_rfm(order_count, dormant_days) where rfm is distinct from …` — เรียกตอน migration (เพื่อให้ Hot เกิด) และตอนบันทึกตั้งค่า
- ต้องวัดเวลาใน dry run: refresh รอบแรกของวันเขียนทุกแถว (~18k) trigger ต้องไม่ทำให้ช้าลงจนมีนัย และ `dsales_rfm_apply()` ต้องจบในเวลาต่ำกว่า `statement_timeout` 8 วินาทีของ `authenticated` มาก (ถ้าไม่ผ่าน ให้เปลี่ยนเป็น join ทั้งชุดกับตารางกติกาแทนเรียกฟังก์ชันรายแถว)

### 4.3 RPC (ทุกตัว `security definer`, เรียก `dsales_uid()`, revoke จาก public/anon, grant ให้ authenticated)

| RPC | ใคร | ทำอะไร |
|---|---|---|
| `dsales_rfm_config_get()` | สมาชิกทุกคน | คืนทุกกลุ่มเรียงตาม `sort_order`: key, ช่วง F/R, is_fallback, tone, behavior, action, template ต่อแบรนด์, no_outreach |
| `dsales_rfm_map(p_scope, p_brand default null, p_as default null)` | สมาชิก | ต่อกลุ่ม: `n` = ลูกค้าทั้งหมดในขอบเขตที่มีกลุ่ม, `contactable` = ในจำนวนนั้นที่ `eligible` (ไม่ซื้อมา ≥ 30 วัน) + แถว `''` = ยังไม่มีกลุ่ม · ขอบเขต/แบรนด์/ตัดลูกค้า CS-B2B/`p_as` ใช้กติกาเดียวกับ `dsales_base_segment_counts` (`mine` / `pool` / `team` เฉพาะหัวหน้า) |
| `dsales_rfm_config_preview(p_segments jsonb)` | หัวหน้า | ไม่เขียนข้อมูล: คืนต่อกลุ่ม `now` / `after` (จำนวนทั้งฐาน ตามกติกาปัจจุบัน / กติกาที่ส่งมา) |
| `dsales_rfm_config_save(p_segments jsonb)` | หัวหน้า | ตรวจ → เขียนตาราง → `dsales_rfm_apply()` → คืน config ใหม่ · ถือ advisory lock ตัวเดียวกับ refresh ฐานลูกค้า กันชนกับ cron |

ตรวจตอน preview/save (`invalid_rfm_config`): ครบ 10 key ไม่ซ้ำ, `f_min ≥ 1`, `r_min ≥ 0`, ค่า "ถึง" ว่างหรือ ≥ "ตั้งแต่", Lost เป็น fallback ท้ายสุด, tone ≤ 40 ตัวอักษร, behavior/action ≤ 500, template ต้องเป็นของแบรนด์นั้น · ไม่ใช่หัวหน้า → `forbidden`

### 4.4 "ไม่ส่งข้อความเป็นชุดให้กลุ่มนี้"

`dsales_outreach_preview` / `dsales_enqueue_outreach` ข้ามลูกค้าที่กลุ่มตั้ง `no_outreach = true` ด้วยเหตุผลใหม่ `rfm_no_outreach` (แสดงใน popup ส่งข้อความเหมือนเหตุผลข้ามอื่น) — บังคับที่ server เพื่อให้ตัวเลือกนี้มีผลทุกหน้า (ลูกค้าของฉัน ถังกลาง Direct Sale) ไม่ใช่แค่ซ่อนปุ่ม
ส่วนนี้แยก migration/test ของตัวเองได้ (`dsales_rfm_no_outreach`) ทำหลังส่วนอื่นเสร็จ

### 4.5 SQL test (`supabase/tests/32_rfm_config.sql`, `33_rfm_no_outreach.sql`)

- seed: `dsales_rfm` ให้ผลเท่ากติกาเดิมทุกจุดขอบ ยกเว้น (1, 0–30) = Hot
- ทุกแถวของ `dsales_customer_base`: `rfm` = `dsales_rfm(order_count, dormant_days)` · trigger ทำงานเมื่อ update `dormant_days`
- preview ไม่เขียนข้อมูล และ `after` ของกติกาเดิม = `now`
- save: เปลี่ยนขอบ Warm/Cold แล้วจำนวนเปลี่ยนตาม preview, ค่าไม่ถูกต้องแต่ละแบบ → `invalid_rfm_config`, เซลล์ → `forbidden`
- `dsales_rfm_map`: ผลรวม `n` + ไม่มีกลุ่ม = จำนวนลูกค้าในขอบเขต, `contactable` ต่อกลุ่ม = `dsales_base_segment_counts`, เซลล์ขอ `team` ได้ผลว่าง, `p_as` เฉพาะหัวหน้า
- no_outreach: เปิดให้กลุ่มหนึ่ง → preview ข้ามด้วย `rfm_no_outreach`, enqueue ไม่เข้าคิว
- regression ที่ต้องรันซ้ำ: `22_rfm_segments` (แก้ให้รู้จัก Hot), `31_lead_json_rfm`, `09_base_customers_chat`, `23_admin_view_as`, `08*` ของ outreach · ไม่รัน 04/04b/25

## 5. หน้าเว็บ

### 5.1 เส้นทางและเมนู

- `/rfm` — หน้า "กลุ่มลูกค้า RFM" ทุกคนเข้าได้ · เมนูซ้ายกลุ่ม "ฐานลูกค้าเก่า" ต่อจากถังกลาง ป้ายเมนู **"กลุ่ม RFM"** (สั้น สำหรับมือถือ)
- `/rfm/settings` — "ตั้งค่า RFM" เฉพาะหัวหน้า (เซลล์เปิดตรง ๆ → กลับ `/rfm`) เข้าจากปุ่ม "ตั้งค่า RFM" บน topbar ของ `/rfm`
- `RouteKey` เพิ่ม `'rfm'` (ทั้งสอง path) · config โหลดครั้งเดียวตอนเปิดแอป (พร้อมทีม/แคมเปญ/ลีด) เก็บใน state กลาง และโหลดใหม่หลังบันทึกตั้งค่า

### 5.2 หน้า `/rfm`

จากบนลงล่าง (ตาม artboard `Main`):

1. **ขอบเขต** (segmented): หัวหน้า = ทั้งทีม (ค่าเริ่ม) / ลูกค้าของฉัน / ถังกลาง · เซลล์ = ลูกค้าของฉัน (ค่าเริ่ม) / ถังกลาง · หัวหน้าในมุมมองเซลล์ = ของเซลล์คนนั้น (`p_as`) · แบรนด์ = แบรนด์ใหญ่ใน topbar เหมือนหน้าอื่น
   ข้างกัน: "จัดกลุ่มแล้ว N ราย · ยังไม่มีข้อมูลการซื้อ N ราย"
2. **แผนที่กลุ่มลูกค้า** (`RfmMap`) — ดูข้อ 5.3
3. **การ์ดแนวทางของกลุ่มที่เลือก** (`RfmActionCard`): ชื่อกลุ่ม + ป้าย tone, จำนวนลูกค้า + สัดส่วนของที่จัดกลุ่มแล้ว + "ติดต่อได้ตอนนี้ N ราย", เงื่อนไขของกลุ่ม (สร้างจากตัวเลขกติกา), พฤติกรรมลูกค้า, แคมเปญแนะนำ, ข้อความเตือนเมื่อกลุ่มตั้ง `no_outreach`, ปุ่ม "ดูรายชื่อ" (เลื่อนไปที่ตาราง)
   ยังไม่เลือกกลุ่ม = การ์ดแสดงคำแนะนำให้แตะกลุ่มในแผนที่
4. **รายชื่อลูกค้า**: `BasePage` เดิมแบบฝัง — ล็อกตัวกรองกลุ่มเป็นกลุ่มที่เลือก ซ่อนแถวชิปกลุ่มลูกค้า ตัวกรองอื่น/ติ๊ก/แถบส่งข้อความ/ปุ่มจองคงเดิม · ขอบเขต "ทั้งทีม" ใช้ scope `team` ของ `dsales_base_customers` (เพิ่มใน `BaseScopeKey`) · ตารางแสดงเฉพาะลูกค้าที่ติดต่อได้ (≥ 30 วัน) ตามกติกาเดิม จึงอาจน้อยกว่าตัวเลขบนแผนที่ — หัวตารางบอกจำนวน "ติดต่อได้ตอนนี้"

กลุ่มที่เลือกและขอบเขตเก็บใน URL (`/rfm?seg=Sleepers&scope=pool`) กลับมาหน้าเดิมแล้วอยู่ที่เดิม

**ต่างจาก mockup โดยตั้งใจ:** ไม่มีปุ่ม "ส่งข้อความกลุ่มนี้" (ส่งด้วยการติ๊กในตารางเหมือนหน้าอื่น เพราะมีเพดานจำนวนต่อชุด) และไม่มีปุ่ม AI จนกว่าจะทำเฟส AI

### 5.3 แผนที่ (`lib/domain/rfm.ts` → `rfmGrid(config)`)

แผนที่ต้องตามกติกาที่ตั้งได้ จึงสร้างจาก config ไม่ใช่วางตำแหน่งตายตัว:

- แกน: ขอบของแถบ F และ R = ค่าขอบทั้งหมดที่ปรากฏในกติกา (ค่าเริ่ม: F = 1 / 2 / 3 / 4–5 / 6+ จากล่างขึ้นบน · R = เกิน 90 / 61–90 / 31–60 / 0–30 จากซ้ายไปขวา)
- แต่ละช่อง (แถบ F × แถบ R) = กลุ่มที่กติกาตัดสินให้ ณ จุดตัวแทนของช่อง · ช่องติดกันที่เป็นกลุ่มเดียวกันรวมเป็นสี่เหลี่ยม (กลุ่มหนึ่งอาจได้มากกว่า 1 สี่เหลี่ยม เช่น Loyal) ชื่อ + จำนวนแสดงบนสี่เหลี่ยมใหญ่สุดของกลุ่ม
- ทุกสี่เหลี่ยมเป็น `<button>` (`aria-pressed`) กลุ่มที่เลือกมีเส้นขอบเข้ม · สีของกลุ่ม = ตัวแปร `--rfm-<กลุ่ม>` / `--rfm-<กลุ่ม>-fg` ใน `styles/tokens.css` (มีค่า dark mode) กลุ่มที่อยู่ติดกันต่างกันที่ความสว่างด้วย ไม่ใช่แค่เฉดสี
- ป้ายแกน: "ความถี่ (F) จำนวนครั้งที่ซื้อ" และ "ซื้อล่าสุด (R) จำนวนวัน" พร้อม "← หายไปนาน / เพิ่งซื้อ →"
- มือถือ (≤ 760px): แผนที่เต็มความกว้าง ป้ายแกนย่อ ("6+", "เกิน 90") บล็อกสูง ≥ 44px หน้าไม่เลื่อนแนวนอน · การ์ดแนวทางและตารางเรียงต่อด้านล่าง (artboard `Mobile`)

### 5.4 หน้า `/rfm/settings` (artboard `Config`)

- ตารางกติกา 10 แถว: ลำดับ, กลุ่ม (จุดสี + ชื่อ), F ตั้งแต่–ถึง, R ตั้งแต่–ถึง, ลูกค้าตอนนี้, ปุ่ม "แนวทาง" · แถว Lost ไม่มีช่องกรอก ("ลูกค้าที่เหลือทั้งหมด")
- ฟอร์มแนวทางของกลุ่มที่เลือก: แนวทางทัก, พฤติกรรมลูกค้า, แคมเปญแนะนำ, template เริ่มต้นของ Bebeplay / Hosttail, ติ๊ก "ไม่ส่งข้อความเป็นชุดให้กลุ่มนี้"
- "ดูผลก่อนบันทึก" → `dsales_rfm_config_preview` แสดงจำนวนต่อกลุ่ม ก่อน → หลัง (เน้นกลุ่มที่เปลี่ยน)
- "บันทึกและคำนวณใหม่" → ยืนยัน → `dsales_rfm_config_save` → โหลด config ใหม่ + toast · กันกดซ้ำด้วย `once`
- ยังไม่บันทึกแล้วออกจากหน้า = เตือนก่อน
- เปลี่ยนลำดับกติกา: ไม่อยู่ในงานนี้ (ลำดับคงที่ตามข้อ 3) — ถ้าต้องการค่อยเพิ่ม

### 5.5 จุดอื่นที่ได้รับผล

- `lib/domain/rfm.ts`: `rfmSegment` / ข้อความกติกา (`rfmRule`) อ่านจาก config (ค่าเริ่มในโค้ด `DEFAULT_RFM_CONFIG` ต้องตรงกับ seed ใน SQL — มี test เทียบ) ใช้กับ tooltip ใน `/mine` `/pool` `/leads` และโหมด fixture
- ชิป "กลุ่มลูกค้า" ใน `/mine` `/pool` (`RFM_OPTIONS`) เพิ่ม Hot · `filtersFromQuery` รับ `rfm=Hot`
- popup ส่งข้อความ: รู้จักเหตุผลข้าม `rfm_no_outreach` ("กลุ่มลูกค้านี้ตั้งค่าไม่ส่งข้อความเป็นชุด") และตั้ง template เริ่มต้นจากกลุ่มเมื่อคนที่เลือกทั้งหมดอยู่กลุ่มเดียวกัน
- `toThaiError`: `invalid_rfm_config`

### 5.6 โหมด fixture

แผนที่นับจากลูกค้าตัวอย่าง (`demoBase` + `rfmSegment` ด้วย config เริ่มต้น) · หน้าตั้งค่าแก้/ดูผลได้ในหน่วยความจำ ปุ่มบันทึกขึ้น toast "โหมด fixture: ไม่ได้บันทึกลง Supabase"

## 6. สิ่งที่เตรียมไว้ให้เฟส AI

`dsales_rfm_config_get()` คืน tone / behavior / action / no_outreach ต่อกลุ่ม และ `dsales_lead_json.rfm` + ฐานลูกค้ามีกลุ่มของลูกค้าแต่ละคนอยู่แล้ว เฟส AI จึงประกอบบริบทต่อคนได้จาก: กลุ่ม + Action Context ของกลุ่ม + ประวัติซื้อ/แชตที่ `dsales_ai_status_context` ใช้อยู่ — งานนี้ไม่สร้างคอลัมน์หรือ route ของ AI ล่วงหน้า

ทิศทางที่คุยกับผู้ใช้ไว้ 2026-11-26 (ยังไม่ได้ออกแบบ ต้องมี spec ของตัวเอง): ปุ่ม "AI ช่วยเขียนข้อความ" ที่ใช้ Action Context ของกลุ่ม RFM
- วางใน popup ส่งข้อความ (ใช้ได้จากทุกหน้าที่ติ๊กลูกค้า: ลูกค้าของฉัน ถังกลาง Direct Sale กลุ่ม RFM) ไม่ใช่ปุ่มแยกรายหน้า
- ขั้นแรก: ร่างข้อความ 1 ฉบับต่อกลุ่ม RFM ของคนที่เลือก (ยังมี `{ชื่อ}` ให้ระบบแทน) เซลล์แก้/ยืนยันก่อนส่งเสมอ · ขั้นถัดไป: ร่างรายคนจากประวัติซื้อ/แชต สำหรับลีดใน Direct Sale ทีละราย
- AI ห้ามแต่งโปร/ราคาเอง ใช้ได้เฉพาะข้อเสนอที่เซลล์หรือหัวหน้ากรอก · กลุ่มที่ตั้ง `no_outreach` ไม่ร่าง · มีเพดานต่อวันแบบ `ai_daily_limit`
